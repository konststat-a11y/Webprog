# Лабораторна робота №2. Основи Bootstrap

**Варіант 9:** сайт приватного медичного центру «Лінія».

## Запуск

Відкрийте `index.html` у браузері. Збирання та встановлення пакетів не потрібні. Bootstrap 5.3.0 та фотографії збережено локально: сайт працює без інтернету. Для перевірки через локальний сервер можна використати Live Server у VS Code.

## Структура

- `index.html` — семантична HTML5-сторінка з усіма обов’язковими секціями.
- `style.css` — тема клініки, адаптивність, CSS-змінні, Flexbox, Grid, градієнти та hover-переходи.
- `script.js` — вибір лікаря, фільтрація за напрямком, перевірка анкети й мобільне меню.
- `vendor/` — оригінальні Bootstrap 5.3.0 CSS та JavaScript Bundle з jsDelivr. Ліцензійні заголовки збережено.
- `assets/` — локальні фотографії Unsplash та SVG favicon.
- `GEMINI_PROMPTS.md` — промпти для виконання передбаченого роботою етапу в Gemini.
- `TESTING.md` — результати перевірки та межі тестування.

## Відповідність варіанту

1. Навігація: логотип, посилання на секції, телефон із `tel:`, кнопка запису, Bootstrap Collapse на мобільних.
2. Hero: опис клініки, фотографія, дві кнопки дії.
3. «Наші напрямки»: чотири Bootstrap cards у сітці `row`, `col-sm-6`, `col-lg-3`.
4. Команда: три картки з фотографіями, спеціалізаціями та прикладами досвіду, кнопки вибору фахівця.
5. Форма: ім’я, телефон, напрямок, залежний список лікарів, бажана дата, необов’язковий e-mail, підтвердження навчального режиму.
6. Ліцензії та сертифікати: три явно позначені навчальні зразки без вигаданих офіційних реквізитів.
7. Footer: графік роботи, контакти та навігація.

Клініка, адреса, телефон, імена та досвід лікарів — вигадані навчальні дані. Фотографії ілюстративні, реальні особи на них не ототожнюються з профілями. Сайт не підтверджує існування клініки, акредитацію чи кваліфікацію. Для реального медичного закладу потрібно замінити приклади на перевірені дані та справжні документи.

## Bootstrap і CSS

Використано `container`, `row`, адаптивні `col-*`, `navbar`, `collapse`, `card`, `btn`, `form-control`, `form-select`, `form-check`, `alert` та utility-класи. Власна тема підключена після Bootstrap. Сітка змінюється на межах 576, 768 та 992 px. Сайт не використовує сторонніх вебшрифтів; SVG-іконки вбудовано без бібліотеки.

Документація: [Navbar](https://getbootstrap.com/docs/5.3/components/navbar/), [Grid](https://getbootstrap.com/docs/5.3/layout/grid/), [Cards](https://getbootstrap.com/docs/5.3/components/card/), [Forms](https://getbootstrap.com/docs/5.3/forms/overview/).

Враховано клавіатурний фокус, skip-link, підписи полів, `aria-live`, `alt`, lazy loading та `prefers-reduced-motion`. Власний JS не вставляє введені дані як HTML і не використовує зовнішні сервіси чи сховище браузера.

## Форма

Це демонстрація для статичного хостингу. Вона **не надсилає заявку**, не бронює час і не зберігає дані. Приклад успішної перевірки показується під формою. Потрібні заповнені ім’я, телефон із 10–15 цифр, напрямок, сумісний лікар, дата не раніше поточної та прапорець навчального режиму. Якщо вказаний e-mail, браузер перевіряє його формат. Бажана дата не є підтвердженням доступного прийому.

Без JavaScript кнопка перевірки вимкнена. Для реального запису потрібні серверна частина, розклад, захищена обробка даних та повідомлення користувачу про правила обробки.

## Робота з Gemini

Цю версію підготовлено в Codex. Звернення до Google Gemini та отримання відповіді від нього **не виконувались**. Файл `GEMINI_PROMPTS.md` містить готовий початковий промпт і запити для ітерацій. Якщо викладач вимагає саме роботу з Gemini, виконайте ці запити у своєму обліковому записі, збережіть реальні відповіді або скриншоти та опишіть власні зміни. Готові промпти не є доказом використання Gemini.

## Публікація на GitHub Pages

1. Створіть репозиторій `web-lab-9`.
2. Завантажте **вміст папки ЛБ2** у корінь репозиторію. Обов’язково додайте `vendor` та `assets`.
3. У Settings → Pages оберіть Deploy from a branch, гілку `main` та `/ (root)`.
4. Після розгортання скопіюйте фактичне посилання GitHub Pages.
5. Здайте посилання на репозиторій та сайт, додайте свідчення роботи в Gemini, якщо це вимагається.

Репозиторій не створювався, сайт не публікувався — цей етап, як і в ЛБ1, залишається вам.
